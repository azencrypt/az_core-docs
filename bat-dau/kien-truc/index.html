Server quyết định

⚠️

Client chỉ gửi yêu cầu. Server kiểm lại tất cả (quyền, job, trực ca, khoảng cách tính từ ped phía server, số lượng, cooldown) rồi mới làm và trả kết quả. Không bao giờ tin số liệu client gửi lên: tiền, item, toạ độ, kết quả minigame.

Ví dụ gọi cấp cứu: người đang gục bấm G → client callServer('gov:distress') → server kiểm người đó đang gục thật, cooldown → tạo đơn medic trên app GOV cho bác sĩ đang trực.

Socket

Client script FiveM không có WebSocket. Vì vậy NUI (web/src/socket.ts) giữ kết nối socket.io tới server (az_socket_public_url), nhận event rồi chuyển xuống client script. Client script phát lại bằng emit() local, nên handler onNet(...) có sẵn vẫn chạy bình thường.

  • Server gửi client: Socket.emitTo(src, event, ...args) thay cho emitNet; Socket.broadcast thay cho emitNet(-1, ...).
  • Client gửi server qua socket: server phải đăng ký Socket.onClient(event, handler) (whitelist). Event chưa đăng ký sẽ bị bỏ qua.
  • Token được cấp khi player load (server/modules/socket). Player tự join room theo job / group (job:police…).
  • Namespace /admin dành cho app ngoài, xác thực bằng convar az_socket_admin_token.
  • Khi socket chưa nối, nhiều chỗ tự chuyển sang dùng emitNet / callback.

Luồng vào game

  1. modules/connection kiểm identifier (Config.IdentifierType), ban (az_bans), DB đã sẵn sàng chưa.
  2. Client sẵn sàng → Events.PlayerReady → PlayerManager.load(src) đọc hoặc tạo dòng az_users → tạo Player.
  3. Chưa có appearance → cho vào routing bucket riêng và mở màn tạo nhân vật. Lưu xong thì về bucket 0, spawn ở Config.Character.NewbieSpawn.
  4. Có nhân vật → Events.PlayerLoaded gửi xuống client, server bắn event nội bộ Events.Local.PlayerLoaded.
  5. Định kỳ: lưu vị trí (PositionSyncInterval), autosave (AutoSaveInterval), trả lương (PaycheckInterval).
  6. Thoát game: PlayerManager.unload lưu DB, các module tự dọn dữ liệu khi có playerDropped.

Player (server)

PlayerManager.get(src) trả về instance Player (src/server/modules/player/Player.js).

Thuộc tính
source, id, identifier, name, charName, charDobid = id nhân vật (az_users.id)
accountstiền theo tài khoản: cash, bank, coin…
job, onDutyjob gồm name và grade; onDuty không lưu DB
groupuser / mod / admin / superadmin
metadatahunger, thirst, level, exp, isDead, licenses, vip…
appearancenull = chưa tạo nhân vật
Method
getMoney(acc), addMoney(acc, n, reason), removeMoney(acc, n, reason), setMoney(...)tiền
getJob(), setJob(name, grade), setDuty(on)job / ca trực
hasPermission(group), setGroup(group), getGroupLevel()quyền
getMeta(key, fallback), setMeta(key, value)metadata, tự sync xuống client
notify(message, type, length, title)thông báo

Muốn lưu thì gọi PlayerManager.saveSoon(src): nó gom lại và ghi sau vài giây, thay vì ghi DB ngay mỗi lần đổi.

Client & NUI

  • Client giữ bản sao dữ liệu player trong client/modules/playerData. Các module đọc từ đó, không hỏi server liên tục.
  • Toàn bộ giao diện là 1 trang (web/build/index.html). Mỗi tính năng là 1 App React mount trong web/src/main.tsx. Xem NUI.
