Quy tắc code

Bắt buộc

  1. Mỗi tính năng 1 thư mục, 1 class Feature (Feature & Loader). Mỗi job 1 thư mục jobs/<job>/.
  2. Dùng lại lib/, không tự viết lại. Có sẵn: NUI (client/lib/nui), callback (callServer), toạ độ / khoảng cách (server/lib/geo), chống spam (server/lib/cooldown), kiểm job (server/lib/job), rate limit, notify. Xem Thư viện.
  3. Server quyết định: client chỉ gửi yêu cầu, server kiểm quyền / job / trực ca / khoảng cách (từ ped phía server) / số lượng.
  4. Tên event đặt trong src/shared/events.js. Callback đặt tên theo dạng module:hanhDong (license:show, gov:desk).
  5. Config để trong shared/, không hard-code con số trong logic: dùng Config.X hoặc shared/jobs/<job>.js.
  6. Bảng DB mới phải là migration, không viết CREATE TABLE trong code tính năng, không sửa câu migration cũ.
  7. Không viết comment giải thích: không có khối comment đầu file, không mô tả từng hàm hay biến (tốn token khi đọc code). Tên hàm và biến phải tự rõ nghĩa. Chỉ viết 1 dòng ngắn khi code làm điều không hiển nhiên (né lỗi FiveM / CEF, thứ tự bắt buộc…). Mô tả API đặt trong docs, không đặt trong code. Riêng src/shared/** (config, items, jobs, công thức dùng chung) giữ comment để biết cách chỉnh config.
  8. Thông báo cho người chơi viết tiếng Việt. Chữ vẽ bằng font GTA (DrawText 3D) phải viết không dấu, vì font GTA không có dấu.
  9. Event hệ thống mà nhiều module cùng nghe (onResourceStop, playerDropped…) thì dùng onEvent / onResourceStop trong @shared/lifecycle, để không bị cảnh báo quá 10 listener.
  10. Trong bundle webpack, đăng ký export bằng global.exports(...) / globalThis.exports(...), không gọi exports(...) trực tiếp.

NUI

⚠️

CEF của FiveM tương đương Chrome 103. Không dùng API JS / CSS ra đời sau đó (ví dụ Array.prototype.toSorted, CSS nesting gốc…). Vite đã đặt target: chrome103 nhưng chỉ chuyển cú pháp, không thêm API còn thiếu.

  • Đường dẫn tài nguyên dùng dạng tương đối (base: './'). File tĩnh đặt trong web/public/<tính năng>/.
  • Gọi client script bằng fetchNui, nghe message bằng useNuiEvent. Không tự fetch sang host ngoài (CEF chặn Mixed Content).

Bảo mật

  • Không commit token / mật khẩu / connection string thật. Token đặt bằng set, không dùng setr.
  • Mọi callback và socket event đều phải kiểm src có Player, có quyền, và giới hạn kiểu / kích thước dữ liệu đầu vào. Xem ví dụ ở server/modules/progress: prop được lọc trước khi ghi vào state bag.
  • State bag chỉ server được ghi (Player(src).state.set(k, v, true)), client chỉ đọc.
  • Thao tác dễ bị spam phải có cooldown (Cooldown.create(ms)).

Checklist trước khi gửi code

  • npm run build không lỗi (core + web).
  • restart az_core: mọi module ✓, không có ✗.
  • Thử trong game đúng luồng vừa sửa và các trường hợp lỗi: đi xa, chết, thoát game giữa chừng, bấm liên tục.
  • PR ghi rõ phần nào chưa thử trong game.
  • Thêm callback / export / config mới thì cập nhật docs (export: sửa docs/scripts/api-data.js rồi npm run gen:api).
