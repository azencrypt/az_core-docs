Bắt đầuaz-api (API ngoài)

az-api (API ngoài FXServer)

az-api (thư mục FXSource/az-api) là một tiến trình Node riêng, chạy cùng máy với FXServer, do az_core tự bật. NUI gọi thẳng HTTP tới nó thay vì đi qua fetchNui → client → server. Logic vẫn nằm trong az_core: az-api chỉ chuyển yêu cầu sang az_core qua kênh nội bộ (bridge).

Hiện mới chuyển quest. Socket.io cũ giữ nguyên, các module khác chuyển dần.

Vòng đời

Sự kiệnaz-api
ensure / restart az_coreaz_core tắt bản cũ (nếu còn) rồi bật bản mới
stop az_corebị tắt theo
FXServer tắt / sậptự thoát sau ≤ 2 giây (theo dõi pid của FXServer)
az-api sậpaz_core bật lại, chờ tăng dần 1s → 2s → … tối đa 30s

Lệnh console: azapi (xem trạng thái), azapi restart.

Cài đặt

Cài thư viện

cd FXSource/az-api
npm install

Thiếu node_modules thì az_core chỉ cảnh báo, NUI tự dùng socket / callback.

Token GM (az-api/.env)

az-api/.env
AZ_API_GM_TOKEN=CHUOI_BI_MAT

Để trống = tắt các route /gm (trả 503 gm_disabled). File .env đã nằm trong .gitignore.

Tuỳ chọn khác trong .env:

BiếnMặc địnhÝ nghĩa
AZ_API_GM_TOKENStrốngtoken riêng từng GM, dạng Tên:token cách nhau bằng , hoặc xuống dòng (token ≥ 16 ký tự). Dùng token nào thì tên người sửa lấy theo token đó, header x-gm-name bị bỏ qua. Dùng chung được với AZ_API_GM_TOKEN
AZ_API_TRUST_PROXYtắtđặt khi az-api nằm sau reverse proxy để khoá sai token theo IP thật của GM. Nhận số proxy đứng trước (1), danh sách IP / dải proxy (127.0.0.1,10.0.0.0/8, loopback), hoặc true
AZ_API_CORE_DIRtự dò ../resources/**/az_corethư mục az_core, dùng để tìm item trong src/shared/battlepass.js khi kiểm tra item còn được dùng
⚠️

Không bật AZ_API_TRUST_PROXY khi az-api mở thẳng ra ngoài: lúc đó ai cũng gửi được X-Forwarded-For giả để né khoá IP. true tin mọi proxy, chỉ dùng khi cổng az-api chỉ proxy gọi được; nên đặt số proxy hoặc IP proxy.

⚠️

NUI chạy ở origin https://cfx-nui-.... Với 127.0.0.1 thì gọi http:// được. Người chơi ở máy khác cần URL công khai, khi đó nên dùng HTTPS / WSS (reverse proxy) và mở firewall cổng az_api_port.

Đường gọi từ NUI (web/src/api.ts)

const data = await azCall('quest:get', [], { api: { method: 'GET', path: '/api/quest' } });
const r = await azCall('quest:action', [act, key], {
  api: { method: 'POST', path: '/api/quest/action', body: { act, key } },
  nui: { act, key },
  write: true,
});

Thứ tự thử: API HTTP → socket.io của az_core → NUI callback (fetchNui(name)).

Lỗi ở bước trướcĐọcGhi (write: true)
không kết nối được, 401, 503 bridge_offline, socket_offlinethử bước sauthử bước sau
timeout (6s), 504, lỗi từ serverthử bước sautrả null, không gửi lại (tránh nhận thưởng 2 lần)

Token phiên NUI: az_core cấp khi PlayerLoaded → client SendNUIMessage('api:connect', { url, token }). Gặp 401 hoặc push đóng mã 4001 / 4002 thì NUI tự xin lại (api:requestAuth, tối đa 1 lần / 5s).

Push (server → NUI)

WS /push: NUI gửi { t: 'auth', token }, nhận { t: 'ready' }. Mỗi { t: 'push', event, data } được phát lại thành message { action: event, data }, nên useNuiEvent(event, ...) dùng như cũ.

Kết nối chưa gửi auth bị đóng sau 5s (mã 4001). Mỗi IP giữ tối đa 16 kết nối chưa xác thực, toàn bộ 512; quá thì az-api trả 429 ngay lúc bắt tay. Path WS khác /push / /bridge bị trả 404.

Phía server: Api.push(src, event, data) trả false khi NUI người đó chưa nối push, lúc đó gọi đường cũ:

Api.push(src, 'quest:update', data) || player.triggerEvent('az_core:quest:update', data);

Thêm handler (server az_core)

const Api = require('../api');
Api.expose('quest:get', (src) => ...);

expose đăng ký cùng một hàm cho cả 3 đường: Callbacks (NUI callback), Socket.onClient, và bridge fx.call. Route bên az-api chỉ chuyển tiếp: forward(req, res, 'quest:get', args).

Route cho resource khác

Resource khác đăng ký bằng export RegisterApiAction(name, handler) và không cần thêm route:

MethodPathHandler
GET / POST/api/res/<resource>/<name> (body / query = payload)bridge res.call → handler(src, payload)

Token cho NUI của resource đó lấy bằng export client GetApiAuth() và event az_core:apiAuth. Cùng handler đó cũng nhận được qua SocketRequest / TriggerServerCallback tên <resource>:<name>. Mẫu đầy đủ (Lua + NUI): resources/[dev]/gtago_template_api.

Route GM (cho tool chỉnh config)

Header Authorization: Bearer <AZ_API_GM_TOKEN>, tuỳ chọn x-gm-name: <tên> để ghi người sửa. Tên có dấu thì gửi dạng encodeURIComponent (header HTTP chỉ nhận ASCII), API tự giải mã và cắt còn 64 ký tự.

Tên gửi qua x-gm-name là tên tự khai: ai có token chung cũng đặt được tên bất kỳ. Khi dùng token chung AZ_API_GM_TOKEN, log az-api ghi tên (tự khai, IP ...) và az_core nhận người sửa là tên (tự khai); cột updated_by vẫn giữ tên đã khai. Muốn tên đáng tin thì cấp token riêng qua AZ_API_GM_TOKENS, khi đó tên lấy theo token.

Sai token trả 401 { error: 'unauthorized', attemptsLeft }. Sai 5 lần thì IP đó bị khoá 60s: 429 { error: 'locked', retryAfter } kèm header Retry-After (giây). IP lấy theo AZ_API_TRUST_PROXY ở trên.

Thưởng onlineGift gồm item, money (cash / bank) và { type: 'vehicle', model, label? }. Xe được cấp biển số mới và cất vào garage. Chưa có dòng trong DB thì az_core dùng mặc định trong file shared, nên sửa file shared vẫn có tác dụng. Lưu config (PUT / DELETE):

  • Thiếu rev → 400 rev_required. Sai hình dạng (thiếu mảng Quests / Milestones / Shops, không phải object) → 400 invalid_value.
  • FXServer đang nối thì az-api gọi config.validate trên az_core trước (chạy thử, không đổi config đang dùng). Có lỗi (trùng key / trùng phút, sai kind, item không tồn tại, giá ≤ 0, job không có, server / inventory / fishing sai kiểu…) → 422 { error: 'invalid_config', errors, warnings }, không ghi gì. Chỉ có cảnh báo thì vẫn lưu và trả warnings.
  • Ghi trong transaction SELECT ... FOR UPDATE. rev không khớp bản đang lưu (GM khác vừa sửa) → 409 { error: 'conflict', rev, source, value, updatedBy, updatedAt }, không ghi gì.
  • FXServer chưa nối thì vẫn lưu (chỉ qua kiểm hình dạng), trả validated: false, applied: false. az_core kiểm lại khi khởi động.

Khi az_core nạp config từ DB mà có lỗi (hoặc JSON hỏng): ghi lỗi ra console và giữ config đang chạy, lần nạp đầu thì dùng mặc định trong file shared. Lưu xong áp dụng ngay vào Config (hoặc config câu cá) và gửi xuống người chơi đang online. Số ô / kg của kho đã mở chỉ đổi khi người chơi vào lại.

Item (/gm/itemdefs) không lưu trong az_config mà ghi thẳng src/shared/data/items.json. Lỗi: 409 conflict (item đã bị sửa, kèm rev và def mới), 404 not_found, 400 sai dữ liệu (label_invalid, name_invalid…), 403 generated_item, 500 write_failed (không ghi được file), 503 bridge_offline, 504 bridge_timeout.

Xoá item: az-api tìm item trong config quest / onlineGift / shop / server / inventory / fishing / tutorial (bản DB, chưa có thì bản mặc định qua bridge; tutorial gồm quà từng bước), ammo / components của item khác, kho đồ người chơi (az_users.inventory, az_inventories), battlepass.js. Còn chỗ dùng → 409 { error: 'item_in_use', usedBy, unchecked }, không xoá. unchecked = nguồn không đọc được (DB / bridge lỗi). Xoá cưỡng bức (force=1) được ghi log cảnh báo; các chỗ trên sẽ trỏ tới item không còn.

curl -H "Authorization: Bearer CHUOI_BI_MAT" http://127.0.0.1:30126/gm/config/quest

Giá BTC Binance cho tab Đầu tư

Giao dịch phái sinh trong GO Bank chỉ có BTC, lấy giá thật từ Binance (API công khai, không cần key, không cần cài gì thêm). Chỉ lấy giá: lệnh, ký quỹ, lãi / lỗ vẫn là tiền trong game, không có lệnh nào đặt lên sàn. Từ 2026-11-19 đã bỏ vàng / dầu / NAS100 và bỏ hẳn MT5 (EA, route /mt5, AZ_API_MT5_TOKEN).

Binance (bookTicker 1 giây / lần, klines 15m + 1m) ──▶ az-api (modules/feed/binance.js) ──bridge feed.ticks / feed.history──▶ az_core (phone/invest.js)
  • Nguồn giá chọn ở Invest.Trade.Feed.Source (src/shared/invest.js, sửa được trong az-tool trang “Đầu tư” → “Nguồn giá”): 'binance' (mặc định) hoặc 'sim' (giả lập). Ở 'sim', az-api thấy az_core trả source: 'sim' thì giãn ra 30 giây mới hỏi lại.
  • Mất giá: quá StaleMs (15 giây) az_core không nhận giá từ az-api (az-api tắt, máy không ra được Internet, Binance chặn…). Tick cuối cũ hơn MaxTickAgeMs (3 phút) thì coi là đóng cửa (BTC chạy 24/7 nên gần như không gặp). Khi đó giá đứng, khoá mở / đóng lệnh (lỗi invest_feed_offline / invest_market_closed), không khớp TP / SL / lệnh chờ / cháy tài khoản. Huỷ lệnh chờ, sửa TP / SL vẫn được. NUI thay 2 nút LONG / SHORT bằng khung “Thị trường đang đóng cửa” / “Mất kết nối giá”.
  • Tick lệch quá MaxJump (20%) so với tick trước bị bỏ (log cảnh báo). Lệch liên tục 5 tick thì nhận (giá thật đã đổi).
  • az_core khởi động lại hoặc mất giá một lúc thì trả need: 'btc' kèm bars (số nến 15m cần, đủ Candles nến khung lớn nhất). az-api tải klines 15m từ Binance (1000 nến / lần, lùi dần) rồi gửi feed.history. Lỗi thì 60 giây sau mới thử lại. Chưa có lịch sử thì vẫn tính là mất giá.
  • Khung 1m dùng chuỗi nến 1 phút riêng: az_core trả thêm fine: 'btc' + fineBars (61 + 1), az-api tải klines 1m và gửi feed.history kèm interval: '1m'. Thiếu lịch sử 1m KHÔNG khoá lệnh, chỉ biểu đồ 1m ít nến tới khi tải xong. az-api bản cũ không gửi 1m thì khung 1m chỉ có nến từ lúc nhận giá.
  • Ở chế độ binance không dùng base, dayVol, Reversion. Giá bán = bid thật, giá mua = bid + spread (mặc định $50 = 0,5 pip, 1 pip = $100), giống chế độ sim.
  • Phí fee ($1 / mini, micro tính theo tỉ lệ, làm tròn lên số đô nguyên) thu 1 lần lúc mở lệnh thị trường / đặt lệnh chờ. Huỷ lệnh chờ hoàn ký quỹ + phí.
  • Netting: mỗi mã 1 vị thế đang mở. Lệnh cùng chiều gộp vào (giá vào trung bình theo khối lượng, ký quỹ cộng dồn, giữ TP / SL cũ). Lệnh ngược chiều đóng bớt đúng khối lượng đó, bằng hoặc lớn hơn thì đóng hết, không mở chiều ngược lại, không thu ký quỹ / phí. Lệnh chờ tách riêng tới khi khớp mới gộp / đóng bớt.
  • Không có TP / SL mặc định. NUI: kéo đường giá vào (hoặc giá đặt của lệnh chờ) về phía lãi để đặt TP, về phía lỗ để đặt SL (LONG: lên = TP, xuống = SL; SHORT ngược lại). Đặt xong kéo đường TP / SL để chỉnh, bấm × trên nhãn để bỏ.
  • Console az-api in [feed] gửi lịch sử BTCUSDT 15m: N nến (và 1m), console az_core in [invest] Đã nhận giá Binance. Không ra được Binance thì az-api in [feed] không lấy được giá Binance: ... (1 lần, tới khi nối lại).

Tool GM: az-tool

App desktop (Tauri v2 + React) nằm ở FXSource/az-tool, gọi đúng các route trên. Hướng dẫn build và chạy xem az-tool/README.md.

  • Token GM lưu trong Windows Credential Manager, chỉ phần Rust giữ và gửi đi, giao diện không đọc được.
  • Trang “Quà online” sửa key onlineGift (mốc phút tuỳ ý, thưởng vật phẩm / tiền / xe), trang “Cửa hàng” sửa key shop, “Máy chủ” / “Kho đồ” / “Câu cá” / “Đầu tư” sửa server / inventory / fishing / invest, “Vật phẩm” sửa /gm/itemdefs, các trang còn lại sửa quest.
  • PUT / DELETE gửi kèm rev lúc tải. Gặp 409 thì báo “GM khác vừa sửa cấu hình này”: xem / so sánh bản mới với nháp, hoặc tải bản mới và bỏ sửa của mình. Không có lưu ghi đè.
  • Gặp 422 thì hiện danh sách lỗi trong bảng lưu, chặn lưu tới khi sửa xong.
  • Trang “Vật phẩm” kiểm item theo đúng luật của az_core ngay trên form (báo đỏ từng ô, khoá nút lưu khi còn lỗi). Item đánh dấu xoá hiện danh sách chỗ còn dùng; gặp 409 item_in_use thì chọn giữ lại hoặc xác nhận rồi xoá cưỡng bức.
  • Khi “Về mặc định” (DELETE), nếu máy chủ đang dùng bản trong DB thì tool sao lưu bản đó vào thư mục dữ liệu của app trước khi xoá.
  • Bản nháp chưa lưu được tự lưu trên máy GM, mở lại tool sẽ hỏi khôi phục.
  • Token đi qua HTTP thường. Nếu GM nối từ máy khác qua Internet thì nên đặt az-api sau reverse proxy HTTPS.
