Kho đồ & vật phẩm

Viết lại theo ý tưởng ox_inventory (không có shop). Server giữ toàn quyền: client chỉ gửi yêu cầu (move / use / drop…), server kiểm tra rồi gửi lại những ô thay đổi.

Serversrc/server/modules/inventory/ (index.js, Inventory.js)
Clientsrc/client/modules/inventory/
Webweb/src/inventory/ (v1), web/src/inventory/v2/ (v2)

Giao diện: Config.Inventory.UiVersion (1 = v1, 2 = v2 theo Figma GOS-UI). Server đọc mỗi lần mở kho: sửa từ az-tool (Cấu hình → Kho đồ → Giao diện kho đồ) có hiệu lực lần mở kế tiếp; sửa config.js thì build + restart az_core. | Item | src/shared/data/items.json (dữ liệu), src/shared/items.js (nạp + item sinh tự động) |

Các kho của 1 người

Kho
fastphím nhanh, mỗi ô khai báo ở Config.Inventory.FastSlots (tối đa 9): accept (nhận gì) + level (cấp mở khoá). Không ô nào nhận quần áo / balo / tiền / túi chứa. Không giới hạn kg
pockettúi cá nhân, số ô = Config.Inventory.PocketSlots, kg = PocketWeight
backpackbalo đang đeo. Sức chứa = Config.Inventory.Backpack + cấp nâng cấp của món balo (Upgrade.Stats.backpack: bagSlots, bagWeight). Đồ trong balo lưu ở az_inventories theo metadata.container
safetúi an toàn: chết không rớt, nâng cấp theo metadata.safeLevel. Config.Inventory.SafePocketEnabled = false thì không bỏ vào được và ẩn ở cả v1 / v2 (đồ còn sót vẫn hiện tới khi lấy ra hết)
equipchỉ quần áo, ô i = Config.Inventory.Equipment[i - 1]
wardrobekho thời trang (VIP)
secondarykho phụ đang mở: cốp xe, hộc xe, stash, túi người khác (khi khám người)
  • Vứt đồ tạo ra 1 túi dưới đất, lại gần bấm E để nhặt.
  • Chết thì rớt vũ khí nằm ở phím nhanh (đồ dùng ở phím nhanh giữ lại).
  • Thêm đồ chỉ vào túi (addItem, export AddItem, nhặt đồ dưới đất, cất vũ khí / tháo quần áo): không bao giờ tự vào balo, muốn cất balo thì người chơi tự kéo. Túi đầy thì không nhận (CanCarryItem / GetEmptySlot / CanCarryAmount cũng chỉ tính túi).

Phím nhanh (Config.Inventory.FastSlots)

FastSlots: [
  { accept: 'heavy', level: 25 },   // ô 1: chỉ súng nặng, cấp 25 mới mở
  { accept: 'light', level: 15 },   // ô 2
  { accept: 'melee', level: 10 },   // ô 3
  { accept: 'item',  level: 0 },    // ô 4: đồ dùng nhanh (đồ ăn, thuốc...)
  { accept: 'item',  level: 0 },    // ô 5
],
Trường
accept1 giá trị hoặc mảng: key trong WeaponTypes (heavy / light / melee) = chỉ vũ khí loại đó · weapon = mọi vũ khí · item = đồ không phải vũ khí · any = gì cũng được
levelcấp nhân vật để mở ô. Chưa đủ thì không bỏ vào / rút ra được, giao diện hiện ổ khoá + cấp
labeltuỳ chọn, mặc định lấy theo accept (WeaponTypes[x].label, “Vũ khí”, “Đồ dùng nhanh”, “Phím nhanh”)
widetuỳ chọn, chỉ v1: true = ô dài xếp dọc ở trên, false = ô nhỏ xếp lưới 2 cột bên dưới. Mặc định ô chỉ nhận vũ khí là ô dài
  • Luật nằm ở src/shared/fastSlots.js (server + client), web có bản sao web/src/inventory/fastSlots.ts chỉ để báo lỗi sớm, server mới quyết định.
  • v1: ô dài trước, lưới 2 cột sau, túi an toàn đẩy xuống dưới (nhiều ô quá thì túi an toàn còn 1 hàng, cuộn). v2: tất cả nằm trên thanh phím nhanh, thanh tự thu khoảng cách khi > 8 ô.
  • Sửa được từ az-tool (Cấu hình → Kho đồ → Phím nhanh): settings.js mục Inventory.FastSlots (đổi accept / level / tên có hiệu lực ngay, đổi số ô cần restart). Mục cũ Inventory.WeaponTypes.*.level đã bỏ. Bật / tắt túi an toàn cũng sửa được ở az-tool (Inventory.SafePocketEnabled, có hiệu lực ngay).
  • Dùng “Sử dụng” lên vũ khí ngoài phím nhanh: vào ô trống đầu tiên nhận được nó (đủ cấp).
  • Bản cũ để vũ khí ở equip ô 1–3. Lần đầu vào game sau khi cập nhật, server tự chuyển sang fast (cùng số ô) và dời quần áo lùi 3 ô. Chuyển 1 chiều: quay lại code cũ sau khi đã chuyển sẽ đọc sai ô.
  • Đồ khoá (locked) không giao dịch được.
  • Config.Inventory.UseWeight (mặc định false): tắt thì chỉ giới hạn số ô, giao diện hiện x / y ô; bật thì giới hạn thêm kg theo maxWeight từng kho và hiện kg. maxStack chạy ở cả 2 chế độ. Khi tắt, balo đang đeo còn đồ thì không tháo / cất / đổi / vứt được (phải lấy hết đồ ra trước); khi bật thì balo mang theo đồ bên trong và tính kg (contentWeight).
  • Đồ hệ thống cấp (addItem server, export AddItem, gửi bưu cục: shop, thưởng, nhiệm vụ, câu cá…) có metadata.new = hạn ruy băng MỚI (Config.Inventory.NewItemMinutes, mặc định 60 phút). Nhặt / lấy từ cốp, kho thì không có. new không tính khi so metadata để gộp chồng.
  • Phím: TAB mở kho, 1…N (N = số ô trong FastSlots): vũ khí thì rút / cất, đồ khác thì dùng. R nạp đạn.
  • Config.Inventory.MoneyItemsEnabled (mặc định true, sửa ở az-tool, áp ngay cho người online): bật = tiền mặt là item MoneyItems trong túi + balo. Tắt = item tiền trong túi + balo bị gỡ, số dư giữ nguyên; bật lại = cộng item cho bằng số dư. Item tiền ở túi an toàn / kho / cốp / dưới đất không đổi (lúc tắt chỉ là vật phẩm không giá trị).
  • Config.Inventory.Drop.Enabled (mặc định true, sửa ở az-tool, có hiệu lực ngay): bật = vứt ra thành túi dưới đất ai cũng nhặt được. Tắt = vứt bỏ là mất luôn (ghi log server), balo còn đồ phải lấy ra trước. Rớt súng khi chết vẫn theo DropWeaponsOnDeath.

Khai báo item

Dữ liệu item nằm ở src/shared/data/items.json (khoá = tên item). File được khai báo trong files {} của fxmanifest, nên server và client đều tự đọc lúc khởi động, không chờ server gửi. Các trường giống ví dụ dưới (bỏ comment vì là JSON).

Sửa bằng az-tool (trang Vật phẩm): mỗi lần lưu chỉ gửi 1 item. Server ghi lại file, cập nhật bản đang chạy rồi gửi đúng item đó xuống mọi client (Events.ItemUpdated), không phải restart. Người vào sau: file trong files {} được FiveM đóng gói lúc start resource, nên client mới vào vẫn đọc bản cũ. Vì vậy server giữ danh sách item đã sửa từ lúc start, client vào game gọi Events.ItemChanges 1 lần để lấy bù. Restart az_core thì file được đóng gói lại và danh sách này về rỗng. Sửa tay file JSON thì phải restart az_core. Thêm / đổi đường dẫn trong fxmanifest thì chạy refresh trước.

src/shared/data/items.json (dạng object)
bread: {
  label: 'Bánh mì',
  weight: 100,           // gram / cái
  stack: true,           // false = mỗi cái 1 ô
  maxStack: 20,          // tối đa 20 cái / ô, quá thì sang ô khác (bỏ trống = gộp vô hạn)
  rarity: 'common',      // common | uncommon | rare | epic | legendary | mythic
  description: 'Ăn cho đỡ đói',
  locked: false,         // true = không vứt / không bỏ kho chung / không đưa người khác
  expire: 7,             // hạn dùng (ngày) -> metadata.expire
  type: 'food',
  consume: 1,            // số lượng trừ mỗi lần dùng (0 = không mất)
  client: {
    status: { hunger: 25 },
    anim: 'eat',
    prop: { model: 'prop_cs_burger_01', bone: 18905, pos: [0.13, 0.05, 0.02], rot: [-50, 16, 60] },
    usetime: 2500,
    label: 'Đang ăn bánh mì',
    progress: 'circle',
    disable: { move: true },
    canCancel: true,
    close: true,
    event: 'tenresource:daAn',
  },
},
Trường client
statuscộng hunger / thirst (thang 0–100, số âm là trừ)
anim'eat', 'drink', object có dict + clip + flag, hoặc object có scenario
propvật cầm trên tay khi dùng (1 object hoặc mảng tối đa 2), mọi người đều thấy
usetimethời gian dùng (ms) = thời gian thanh tiến trình, mặc định 2500
labelchữ trên thanh, mặc định “Đang dùng” + tên item
progress'circle' = dùng vòng tròn thay cho thanh
disablekhoá phím khi dùng, mặc định combat + sprint
canCancelfalse = không cho bấm X huỷ
closefalse = dùng xong không đóng kho đồ
eventTriggerEvent phía client sau khi dùng xong

Bấm X / chết / ngã / bị còng / xuống nước trong lúc dùng thì huỷ và không mất đồ. Ảnh item lấy từ CDN theo tên item: https://files.gtago.net/items/TEN.webp (chỉ dùng .webp, không dùng .png), không có thì hiện hình hộp.

Item dùng được (do code xử lý)

const Inventory = require('../../modules/inventory');
 
Inventory.registerUsable('lockpick', async (src, item, invId) => {
  // item: name, count, slot, metadata
  return false; // false = không dùng được
});
exports.az_core:RegisterUsableItem('lockpick', function(src, item, invId)
  return true
end)

Chỉ dùng được khi item nằm trong kho cá nhân. Callback trả false nghĩa là không dùng được.

API server

Method
addItem(src, name, count, metadata)thêm đồ
removeItem(src, name, count, metadata?)bớt đồ
getItemCount(src, name, metadata?)đếm trong túi + balo + phím nhanh
canCarry(src, name, count, metadata)còn chứa được không
findItems(src, name, { fast? })tìm các ô có item trong túi / két / balo; fast: true quét thêm ô phím nhanh
getSlotItem(src, invId, slot) / setSlotMeta(...) / removeFromSlot(...)thao tác theo ô
sendToMail(charId, name, count, metadata) / openMail(src)đồ hệ thống gửi vào kho bưu cục
openSearch(src, target, check, label)mở túi người khác (khám người); check() trả false thì đóng
addActionBlocker(fn)chặn thao tác kho (ví dụ đang bị còng)
registerCreateHook(name, fn)sửa metadata khi item được tạo (ví dụ sinh IMEI điện thoại)
exports.az_core:RegisterHook(event, fn, options)resource khác chặn / sửa kéo đồ, dùng đồ, mở kho, tạo item: xem Hook kho đồ
onPersonalChange(fn)nghe sự kiện kho cá nhân thay đổi
closeFor(src)đóng kho
